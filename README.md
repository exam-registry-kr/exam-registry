한국어 | [English](README.en.md)

진행 중인 시험 문제에 AI가 답하지 않도록 하는 국가 단위 등록 체계의 설계 문서, 시뮬레이션 코드, 실험 결과입니다. 수능에서 시작하여 자격시험, 대학 시험, 학교 내신으로 단계적으로 확대하고, 국제 표준으로 제안하는 것을 목표로 합니다. 누구나 아래 절차에 따라 결과를 직접 확인하고 재현할 수 있습니다.

| 구분 | 내용 |
|---|---|
| 채택한 판정 규칙 | R5 (정의와 값은 3.18). 제출 당시 규칙의 빈틈을 제출 뒤 스스로 찾아 고친 것입니다(3.14). |
| 확인한 것 | 문항을 그대로 입력하거나 띄어쓰기, 문장 순서, 일부 낱말을 바꾼 질문은 99.4~100% 거절합니다(3.7). 문항 앞에 숫자나 무관한 문장을 붙인 질문은 100%(3.18), 여러 메시지로 나눈 질문은 대화 전체를 판정할 때 100% 거절합니다(3.10). 숫자만 다른 연습문제 720건은 한 건도 거절하지 않았습니다(3.18). 시험 기관은 질문을, AI 서비스는 문항 원문을 보지 못한 채 같은 판정이 나옵니다(3.5). |
| 막지 못하는 것 | 문항의 20~60%만 옮긴 짧은 인용은 77.3%만 거절합니다. 문장을 전부 다른 표현으로 바꾼 질문(2.8% 거절), 다른 언어로 옮긴 질문(0%), 두 낱말마다 군말을 끼운 질문(5%). 협조하지 않는 서비스, 직접 설치한 AI, 사람의 대리 풀이. |
| 치르는 비용 | 질문 1건에 조각 약 130개, 조각마다 타원곡선 곱셈 1회(3.11). 연습문제 32개를 한 대화에 이어 붙이면 100건 중 1건을 잘못 거절합니다(3.18). 문항 전문이 든 대화는 시험이 끝날 때까지 거절됩니다(3.17). |
| 아직 재지 못한 것 | 실제 카메라와 실제 인쇄물, 실제 교재와 실제 학습 질문, 신경망 문장 임베딩과의 비교, AI가 바꿔 쓴 문장, 최적화된 구현의 처리량. 전체 목록은 4장에 있습니다. |

5분 안에 직접 돌려 보려면 2.2, 실험 전체의 요약은 3장 첫 표, 한계는 4장을 보시면 됩니다.

## 1. 개요

AI 서비스는 지금 어디서 어떤 시험이 진행 중인지 알 수 없어 시험 부정행위에 대응하지 못하고 있습니다. 시험 보호 국가 등록제는 이 정보를 AI 서비스에 제공합니다. 어린이 보호구역이 학교 주변 도로에만 적용되어 다른 도로의 통행에는 영향을 주지 않듯이, 이 제도는 등록된 시험 문항에만 작동하며 시험이 끝나면 자동으로 해제됩니다.

1\. 시험 등록: 인가된 시험 기관이 시험 전에 시험명, 교시별 시간, 문항 해시(문항을 되돌릴 수 없는 요약값)를 전자서명하여 공개 장부인 국가 등록부에 등록합니다. 문항 원문은 등록하지 않습니다.

2\. 두 가지 열쇠: 협조하는 AI 서비스는 등록된 시간 동안 입력된 사진이나 문장이 진행 중인 시험과 일치하는지 다음 두 가지로 확인하고, 일치하면 답변을 거절합니다. 둘 중 하나만 일치해도 거절하므로, 한쪽이 확인하지 못하는 입력을 다른 쪽이 보완합니다.

가. 문항 내용 조회(핵심): AI 서비스가 입력 문장을 4글자 조각으로 나누어 가린 상태로 시험 기관 서버에 조회합니다(망각 의사난수함수, IRTF RFC 9497). 시험 기관은 사용자의 입력을, AI 서비스는 문항 원문을 볼 수 없습니다. 암호화 조회가 일반 대조와 같은 판정을 내리는지는 3.5에서 확인합니다.

나. 시험지 표식(보조): 시험지 바탕에 시험 번호를 담은 옅은 노란 보안 문양을 인쇄합니다. 보안 문양은 작은 격자형 표식(ArUco)을 반복한 것으로, 시험지 일부만 촬영되어도 시험 번호를 읽을 수 있습니다. 판독은 AI 서비스 내부에서 이루어지며 외부 통신이 필요하지 않습니다. 인터넷 없이 작동하는 기기 내장 AI에는 문항 내용 조회를 쓸 수 없으므로, 휴대폰과 안경 제조사가 등록된 시험 시간 목록을 미리 받아 기기에 표식 판독을 넣는 경우에만 적용됩니다.

3\. 자동 해제와 사후 검증: 등록된 시간이 지나면 제한은 자동으로 해제됩니다. 시험 종료 후 공개되는 문항을 등록된 해시와 대조하면, 시험 문항 외에는 막지 않았는지 누구나 확인할 수 있습니다.

4\. 적발이 아니라 거절: 일치했을 때 일어나는 일은 답변 거절뿐이며, 기본값으로는 개인을 적발하거나 신고하지 않습니다. 시험별 거절 건수만 집계합니다. 교실 번호 추적이나 신고는 정부가 따로 결정할 선택지로만 남겨 두었습니다.

### 운영 체계

| 역할 | 담당 |
|---|---|
| 등록 기관 인가, 교육 분야 AI 서비스 준수 요건 | 교육부 |
| 국가 등록부와 공용 조회 서버 운영 | 국가가 지정한 교육 정보 시스템 운영 기관 |
| 시험 등록과 서명, 표식 인쇄 | 시험 기관 (수능과 모의평가는 한국교육과정평가원, 자격시험은 시행 기관) |
| 학교·대학 시험 등록 | 교육청과 대학 본부의 인가를 받은 교원. 자체 서버 없이 공용 조회 서버를 이용 |
| 판정과 거절, 거절 건수 보고 | 협조하는 AI 서비스 |
| 기기 내장 AI의 표식 판독 | 협조하는 휴대폰·안경 제조사 |

자세한 절차와 협조 요청 방식은 정책 제안서 7장에 있습니다.

국가가 이 체계를 한 번 구축하여 인가와 관리를 맡으면, 같은 등록 규격으로 국가시험뿐 아니라 자격시험, 대학 시험, 학교 내신, 온라인 시험도 등록할 수 있습니다. 같은 규격으로 나라마다 등록부를 운영하고 서로 연동할 수 있습니다.

## 2. 직접 확인하기 (약 5분)

### 2.1 준비

Python 3.10 이상이 필요합니다. 터미널(Windows는 명령 프롬프트)에서 저장소 폴더로 이동한 뒤 다음을 실행합니다.

```
pip install -r requirements.txt
cd code
```

한국어 글꼴이 필요합니다. Windows(맑은 고딕), macOS(Apple SD 산돌고딕 Neo), Linux(Noto Sans CJK)는 자동으로 찾습니다. 찾지 못하면 환경 변수 `EXAM_FONT`에 한국어 글꼴 파일 경로를 지정하십시오.

### 2.2 시연

```
python demo.py
```

시험 등록과 서명 확인, 표식이 인쇄된 시험지의 일부 촬영과 판독, 문항 내용 조회, 채택한 판정 규칙을 차례로 실행합니다(약 1분). 다음과 같은 결과가 출력됩니다.

```
[1] 시험 등록
    등록 기록: {"exam_id": "5A17C0DE", "title": "2027학년도 모의 시험 수학 영역", "policy": "content_match"}
[2] 시험지 표식
    표식 있는 시험지 사진: 시험 번호 5A17C0DE 판독 (조각 6/6) -> 시험 시간 중 거절, 종료 후 정상 답변
    표식 없는 시험지 사진: 표식 없음 -> 정상 답변
[3] 문항 내용 조회
    원문 그대로: 일치율 100%, 숫자 일치 예 -> 거절
    띄어쓰기·표현 변경: 일치율  91%, 숫자 일치 예 -> 거절
    다른 숫자의 같은 유형 문제: 일치율  40%, 숫자 일치 아니오 -> 정상 답변
    무관한 질문: 일치율   0%, 숫자 일치 아니오 -> 정상 답변
[4] 채택한 판정 규칙 R5 (3.18). 괄호 안은 이전 규칙 R3
    등록 문항 그대로: 질문 조각 36개 중 36개 일치 -> 거절 (R3: 거절)
    앞에 "문제 23번"을 붙임: 질문 조각 41개 중 36개 일치 -> 거절 (R3: 정상 답변)
    무관한 문장 3개를 앞에 붙임: 질문 조각 93개 중 36개 일치 -> 거절 (R3: 정상 답변)
    숫자만 다른 연습문제: 질문 조각 36개 중 25개 일치 -> 정상 답변 (R3: 정상 답변)
    문장을 전부 바꿔 씀 (막지 못하는 경우): 질문 조각 43개 중 7개 일치 -> 정상 답변 (R3: 정상 답변)
```

[3]은 조회의 원리를 처음 규칙(조각 일치율과 숫자 검사)으로 보여 주고, [4]는 채택한 규칙 R5를 문항 하나("기차가 43시간 동안 150km를 달렸다. 같은 속력으로 16시간 동안 달리면 몇 km를 가는가?")로 보여 줍니다. 둘째와 셋째 줄이 제출 뒤 찾은 빈틈이고, 마지막 줄은 지금도 막지 못하는 경우입니다.

`demo_out/` 폴더에 표식을 인쇄한 시험지(`page_marked.png`)와 모의 촬영 사진(`photo_marked.png`, `photo_unmarked.png`)이 저장됩니다. 표식의 진하기와 촬영 범위를 바꿔 볼 수 있습니다.

```
python demo.py --ink 0.5 --view 0.25
```

`--ink`는 노란 잉크가 청색광을 흡수하는 비율(인쇄 농도), `--view`는 사진에 담기는 시험지 높이의 비율입니다. `--en`을 붙이면 영어로 출력합니다.

### 2.3 운영 과정 시연

```
python operation_demo.py
```

교육부, 교육청, 등록부 운영 기관, 시험 기관, 인쇄소, AI 서비스, 기기 제조사, 사후 검증자가 각자 가진 정보만으로 움직이는 모의평가 하루를 두 달 전 준비부터 시험 후 검증까지 시간 순서대로 재생합니다(약 15초).

1. 사전 준비: 교육부가 등록부 운영 기관을 지정하고, 평가원을 직접 인가하며, 교육청에 학교 인가 권한을 위임합니다. AI 서비스와 기기 제조사와 협약을 맺습니다.
2. 연동 시험: 30분짜리 가짜 시험을 등록해 AI 서비스가 시험 시간에만 거절하는지 점검합니다.
3. 시험 준비: 문항 확정, 장부에서 쓰지 않은 시험 번호 확인, 문항 조각 암호화, 인쇄, 인쇄 견본 판독 검수.
4. 등록과 배포: 서명한 기록을 등록하고, 미인가 단체, 학교의 수능 종류 등록, 번호 중복, 전송 중 변경, 30시간 차단을 거부합니다. 학교는 문항을 보이지 않고 공용 조회 서버로 조각을 암호화해 등록합니다. 운영 기관이 장부 머리(머클 루트)에 서명하고, 조각 값 묶음은 잠근 채 배포되고 AI 서비스는 장부를 직접 재검증한 뒤 잠긴 묶음을 보관하며(내부자가 미리 대조해 볼 값이 없음, 3.9), 기기 제조사는 시험마다 포함 증명을 확인하고 시험 번호와 시간만 서명해 내려보냅니다(끼워 넣은 목록은 설치 거부). 누구나 다음 날 차단될 시험을 미리 확인합니다.
5. 시험 당일: 시작 시각에 묶음 열쇠 공개와 개봉(변조된 묶음은 폐기), 시험 전, 중, 후의 사진과 문장 입력, 기기 내장 AI, 시작 뒤 추가 등록 시도.
6. 시험 후: 문항 공개와 약속값 대조, 일관성 증명으로 장부가 고쳐지지 않았음을 확인(지난 기록을 고친 장부는 변조로 드러남), 시험별 거절 건수 보고.

단계마다 누가 무엇을 보았고 무엇을 보지 못했는지를 출력합니다. 판정은 실제로 계산한 결과이며 실행할 때마다 같습니다. 결과는 `operation_demo_out/`에 시간표(`operation_demo.html`, `operation_demo.md`)와 사진으로 저장되며, 한 번 실행한 결과를 [`docs/운영과정_시연.md`](docs/운영과정_시연.md)에 올려 두었습니다.

### 2.4 문서에 인용된 수치 확인

```
python summarize_results.py
```

#### 상용 AI로 다시 확인 (E5-003)

문자 인식 프로그램보다 사진을 잘 읽는 상용 AI로도 같은 질문을 확인했습니다. 3.2의 사진 가운데 36장을 AI에 보이기 전에 정한 규칙(`code/e5_stage2.py` 머리말)으로 골랐습니다. 최종 판독기가 표식을 읽지 못한 사진 20장(글자가 가장 큰 순), 그중 2장의 반복, 최종 판독기만 읽어 낸 작은 글씨 사진 10장, 선명한 대조 사진 4장입니다. 사진마다 ChatGPT(화면 표시 모델명 GPT-Astra)에 문제 번호, 읽은 문장, 답을 물었습니다.

| 묶음 | 장수 | 상용 AI가 푼 사진 | 표식 판독 |
|---|---|---|---|
| 최종 판독기가 표식을 읽지 못한 사진 (반복 2장 포함) | 22 | 0 | 0 |
| 최종 판독기만 읽어 낸 작은 글씨 사진 | 10 | 6 | 10 |
| 선명한 대조 사진 | 4 | 4 | 4 |

상용 AI가 푼 사진은 모두 표식도 판독되어, 협조하는 AI 서비스라면 답을 거절했을 사진입니다. 반대로 글자 크기가 6픽셀 안팎인 사진 4장은 상용 AI가 문장을 읽지 못했지만 표식은 판독되었습니다. 9번 사진은 처음에 같은 대화에서 바로 앞에 넣은 같은 시험지 사진(같은 1번 문항)의 내용으로 답했으나, 새 대화에서 사진 한 장만 넣어 두 가지 질문으로 다시 물었을 때는 모두 판독 불가였습니다. 정답은 사진의 시험지 번호로 문항을 다시 만들어 자동으로 채점합니다. 사진, 정답표, 질문, 응답 원문은 `results/E5-003_*`에 있습니다.

### 3.5 암호화 조회가 판정을 바꾸는지와 처리 시간

```
python e7_oprf_lookup.py
```

위 표의 문항 조각 대조 실험(E3)과 같은 실험용 문항 60개, 자동으로 바꿔 쓴 질문 360개, 같은 유형의 연습문제 240개를 E3과 같은 순서로 다시 만들어 씁니다. 같은 판정 규칙(질문의 4글자 조각 중 한 문항에서 찾은 비율이 0.5 이상이고 질문의 숫자가 모두 그 문항에 있음)을 두 방식으로 적용해 비교합니다.

- 비교군(일반 대조): 조각을 암호화하지 않고 해시값으로 대조
- 암호화 조회: 조각을 RFC 9497의 OPRF(P-256, SHA-256) 기본 모드로 가린 채 시험 기관에 조회(`rfc9497.py`, 3.13)

600건 모두 두 방식의 판정, 일치한 문항, 일치 비율이 같습니다. 바꿔 쓴 질문 탐지율과 연습문제 오인율(0%)도 E3 방식과 같습니다. 판정은 실행할 때마다 같고, 처리 시간은 컴퓨터에 따라 달라집니다. 이 구현은 RFC 9497의 공식 시험 값을 통과하지만, 타원곡선 곱셈 외의 계산을 Python으로 하므로 최적화된 라이브러리보다 느립니다(질문 1건당 시험 기관 약 37ms, AI 서비스 측 전체 약 174ms).

### 3.6 등록 문항이 많아질 때 (E8)

```
python e8_registry_scale.py
```

중간고사 기간처럼 많은 학교가 같은 날 시험을 등록하면 등록 문항이 수만 개가 됩니다. 등록 문항을 60개에서 600개, 6,000개, 60,000개로 늘리며 3.5와 같은 질문 600건을 다시 판정했습니다. 늘린 문항은 모두 연습문제와 같은 12개 유형에서 만들어, 학생이 공부하는 문제와 비슷한 문항이 등록부를 채우는 가장 불리한 조건으로 했습니다. 등록 60개에서는 3.5의 일반 대조와 600건 모두 같은 판정이 나오는지 먼저 확인했습니다.

| 등록 문항 | 바꿔 쓴 질문 탐지 | 연습문제 오인 (E7 규칙) | 연습문제 오인 (보완 규칙) |
|---|---|---|---|
| 60 | 99.4% | 0/240 | 0/240 |
| 600 | 99.4% | 0/240 | 0/240 |
| 6,000 | 99.4% | 1/240 | 0/240 |
| 60,000 | 99.4% | 1/240 | 0/240 |

E7 규칙은 질문의 숫자를 종류별로 한 번만 확인합니다. 그래서 "첫째항 68, 공비 68"처럼 같은 숫자가 두 번 나오는 연습문제가, 68이 한 번만 있는 다른 등록 문항과 일치한 것으로 판정되었습니다. 반복된 숫자는 등록 문항에도 같은 횟수만큼 있어야 일치로 보도록 보완하면 6만 개까지 오인이 없었고, 탐지율은 그대로였습니다. 운영 규칙에는 보완 규칙을 권장하며, 시연 코드(`demo.py`, `oprf_demo.py`, `operation_demo.py`)에는 보완 규칙을 적용했습니다. 시연의 판정 결과는 바뀌지 않았습니다. 판정 기준을 일치율이 가장 높은 문항 하나가 아니라 기준을 넘는 모든 문항으로 넓힌 경우도 비교했으며, 이때는 오인이 늘어(6만 개에서 3~5건) 채택하지 않았습니다. 결과 파일에는 오인된 연습문제와 일치한 등록 문항의 원문을 함께 기록했습니다.

### 3.7 한국어 문항과 숫자 없는 문항 (E9)

3.5와 3.6의 문항은 모두 영어로 된 계산 문제였습니다. 그리고 판정 규칙은 질문의 숫자가 등록 문항에 있어야 일치로 보았으므로, 국어나 사회처럼 숫자가 없는 문항은 문항 내용 조회로 보호할 수 없었습니다. 이 실험은 영어 계산형 60개, 한국어 계산형 60개, 숫자가 없는 한국어 서술형 60개(발문, 4~6문장의 지문, ①~⑤ 선지)를 함께 등록하고 세 가지 규칙을 비교했습니다.

- E8 규칙: 3.6의 보완 규칙 그대로

### 3.9 AI 서비스 내부자의 사전 추측 (E11)

```
python e11_insider_guessing.py
```

협조하는 AI 서비스는 등록 문항의 암호화된 조각 값 묶음을 받고, 질문을 조회할 때처럼 아무 조각이나 시험 기관 서버에 암호화해 달라고 할 수 있습니다. 그래서 서비스 내부의 누군가가 조각을 추측해 암호화한 뒤 묶음에 있는지 확인하면, 시험 전에 문항을 복원할 수 있는지를 시험했습니다. 공격자는 일부러 가장 강하게 두었습니다. 실험 문항을 만든 틀과 어휘(문장 틀, 이름, 발문, 주제, 명사)를 모두 알고, 뽑힌 값만 모르는 내부자입니다. 실제 출제 위원은 출제 틀을 공개하지 않으므로 실제 공격자는 이보다 약합니다. 대상은 3.7의 새 문항 중 한국어 계산형 60개와 서술형 60개입니다.

| 측정 | 결과 |
|---|---|
| 숫자 추측(0~999, 반복 포함 3,000회) | 120개 문항 모두 숫자를 전부 알아냄 |
| 계산형 문항 전체 복원 | 60/60 |
| 서술형 문항의 발문, 지문 문장, 선지 복원 | 60/60 (651개 문장 모두) |
| 추측한 서로 다른 조각 수 | 18,605개. 보통 질문 1건의 조각 수(132.6개)로 나누면 약 140건, 시험 기관 서버 CPU로 약 0.1분 |
| 암호화 값으로 직접 확인 | 추측 2,100개 모두 일반 대조와 같은 결과 |

추측에 필요한 양이 보통 질문 약 140건 분량이라, 이용자가 많은 서비스에서는 조회 횟수 제한이나 이상 탐지로 가려낼 수 없습니다. 그래서 조각 값 묶음이 시험 전에 열려 있어서는 안 됩니다. 묶음을 AES-256-GCM으로 잠가 전날 배포하고, 32바이트 열쇠를 시험 시작 시각에 공개하는 방식을 함께 시험했습니다. 시작 전에는 추측 200개 중 일치가 0건이었고, 열쇠를 공개한 뒤에는 묶음이 원래 값과 똑같이 열렸습니다. 운영 과정 시연(2.3)도 이 방식으로 바꾸었습니다. 시험이 진행되는 동안에는 내부자가 같은 방법으로 문항을 알아낼 수 있지만, 그때는 응시자가 이미 시험지를 받은 뒤입니다.

### 3.10 문제를 여러 메시지로 나눠 물을 때 (E12)

```
python e12_split_questions.py
```

한 메시지에 담긴 조각이 적으면 거절 기준에 못 미칠 수 있으므로, 문제를 나눠 보내는 경우를 시험했습니다. 3.7의 새 문항 180개와 제안 규칙을 그대로 썼습니다.

- 그대로 나누기: 문항을 연속된 낱말 묶음 2, 4, 8개로 나눠 하나씩 보냄
- 숫자 따로 보내기: 숫자를 A, B, C로 바꾼 본문을 1, 2, 4, 8개로 나눠 보내고, 마지막에 "A=168, B=75, C=4"를 보냄

| 공격 | 판정 방식 | 영어 계산형 | 한국어 계산형 | 한국어 서술형 |
|---|---|---|---|---|
| 그대로 나누기(2~8개) | 메시지마다 | 100% | 100% | 100% |
| 숫자 따로 보내기(본문 1개) | 메시지마다 | 92% | 58% | 100% |
| 숫자 따로 보내기(본문 8개) | 메시지마다 | 0% | 0% | 100% |
| 숫자 따로 보내기(본문 8개) | 대화 전체 | 92% | 58% | 100% |
| 숫자 따로 보내기(본문 1~8개) | 대화 전체 + 값 되돌리기 | 97% | 100% | 100% |

그대로 나눈 조각은 짧아도 등록 문항의 일부를 그대로 옮긴 것이어서 모두 거절되었습니다. 숫자를 따로 보내면 계산형 문항은 메시지마다 판정할 때 대부분 통과했습니다. 시험 시간 동안 같은 대화의 메시지를 모두 합쳐 판정하고, "A=168"처럼 주어진 값을 본문의 A 자리에 다시 넣으면(문제를 이해하지 않는 단순한 문자 치환) 97~100%가 거절되었습니다. 영어 계산형에서 놓친 3%는 본문의 관사 "A"가 치환 문자와 겹친 경우입니다. 같은 유형 연습문제를 4개 연속으로 묻는 대화 600건과, 연습문제, 발문, 짧은 후속 질문을 섞은 대화 600건은 어느 판정 방식에서도 거절되지 않았습니다.

E14의 규칙(R3)과 이를 포함하는 최종 규칙(R5)은 숫자 없는 질문에 더 많은 조각을 요구하므로 메시지마다 판정할 때는 더 약합니다. 서술형을 8개로 그대로 나누면 메시지마다 0%, 최근 2개 메시지를 합치면 57%가 거절됩니다. 대화 전체를 합쳐 판정하면 모든 공격이 세 종류 모두 100% 거절되었고, 값 되돌리기를 더하면 영어 계산형의 3% 누락도 사라졌습니다(R2 97% → R3 100%). 학습 대화 1,200건은 R3에서도 거절되지 않았습니다. 따라서 R3는 대화 전체 판정과 함께 써야 합니다.

### 3.11 시험 기관 서버의 부하와 연동 확인용 시험 값 (E13)

```
python e13_load_and_vectors.py
python e13_load_and_vectors.py --check
```

시험 기관 서버가 질문마다 하는 일은 조각마다 타원곡선 곱셈 한 번(RFC 9497의 BlindEvaluate)입니다. 이 컴퓨터의 CPU 1개로 조각을 1개, 70개, 1,000개, 10,000개씩 묶어 처리했습니다. 이 저장소의 RFC 9497 구현은 조각당 약 513~541마이크로초, 그 안의 타원곡선 곱셈만 따로 재면 약 58~69마이크로초였고, 둘 다 묶음 크기와 거의 무관했습니다. 차이는 점의 좌표 복원과 인코딩을 Python으로 하기 때문입니다. 묶어 보내도 서버 비용은 줄지 않고, 비용은 조각 수에 비례합니다. 한국어 질문의 조각 수 중앙값(132개) 기준으로 CPU 1개가 이 구현으로 초당 약 15건, 곱셈만의 비용으로는 약 123건을 처리합니다. 가정한 값인 초당 1,000건의 한국어 질문이면 이 구현으로 CPU 약 68개, 최적화된 구현이라면 약 9개가 필요합니다. AI 서비스 쪽에서 한국어 질문 1건을 가리고 되돌리는 데는 이 구현으로 약 374ms가 걸렸습니다.

측정 환경은 클라우드 가상 머신의 Intel Xeon 2.10GHz CPU 1개(스레드 1개), Python 3.13, `cryptography` 50(OpenSSL 4.0)입니다. 위 값은 처음 잰 결과(`results/E13-001_results.json`)이고, 같은 환경에서 다시 잰 결과(`results/E13-002_results.json`, 환경 기록 포함)는 조각당 529~551마이크로초, 곱셈만 57~68마이크로초, CPU 70개와 8개였습니다. 실행할 때마다 몇 퍼센트씩 달라지며, 다른 CPU에서는 값이 달라집니다. GPU나 FPGA로 곱셈을 묶어 처리하는 경우, 여러 CPU에 나눠 처리하는 경우는 재지 않았습니다.

AI 서비스가 자기 구현을 맞춰 볼 수 있도록, 공개한 씨앗값에서 RFC 9497의 키 유도(DeriveKeyPair)로 만든 시험용 키(실제 시험에는 쓰지 않음)로 만든 RFC 9497 출력값을 `results/E13-test_vectors.json`에 두었습니다. 문항 3개(계산형 2, 서술형 1)의 조각과 숫자 토큰, 각 조각의 암호화 값, 발문 조각, 그리고 질문 11개(그대로 입력, 띄어쓰기 제거, 숫자만 다른 연습문제, 반복 숫자, 서술형 원문, 발문만 입력, 선지 번호를 1)로 입력, 계산형과 서술형 앞에 "문제 23번"을 붙인 것, 무관한 문장을 덧붙인 것, 연습문제 앞에 "문제 23번"을 붙인 것)의 조각과 최종 규칙(R5)의 판정을 담았습니다. R3의 판정도 함께 적어 두 규칙이 갈리는 질문을 볼 수 있습니다. `--check`는 이 값을 다시 계산해 그대로인지 확인합니다.

### 3.12 조각 길이와 기준값은 왜 그 값인가 (E14)

E9까지 쓴 값은 조각 4글자, 숫자 문항 일치율 0.5, 숫자 없는 문항 최소 20조각과 일치율 0.6입니다. 이 가운데 0.6만 별도 문항 묶음에서 정했고, 그것도 연습문제 전체를 입력한 경우만 따졌습니다. E14는 모든 값을 같은 방식(선택용 묶음에서 정하고 새 묶음에서 확인)으로 다시 정하고, 값마다 무엇을 얻고 잃는지 보였습니다. 질문에는 문항 일부(낱말의 10~100%)만 옮긴 경우와 연습문제 일부만 입력한 경우를 새로 넣었습니다. 연습문제 일부가 등록 문항의 일부와 글자 그대로 같으면 어떤 내용 규칙으로도 시험 문장과 구별할 수 없으므로 따로 집계했습니다. n=4와 E9 값으로 E9 결과가 그대로 재현되는지 먼저 확인했습니다.

### 3.13 국제 표준 적합성

```
sh check_standards.sh
```

등록제의 두 핵심 장치를 국제 표준 규격 위에 다시 세웠습니다. AI 서비스, 기기 제조사, 다른 나라가 이 저장소의 코드가 아니라 공개된 표준으로 자기 구현을 만들 수 있게 하기 위해서입니다.

| 장치 | 따르는 표준 | 확인한 방법 | 결과 |
|---|---|---|---|
| 암호화 조회 | RFC 9497 OPRF(P-256, SHA-256) 기본 모드, RFC 9380 hash_to_curve P256_XMD:SHA-256_SSWU_RO_ | CFRG 저장소의 공식 시험 값 | hash_to_curve 5/5, 키 유도(DeriveKeyPair) 일치, OPRF 2/2 (가린 값, 서버 계산 값, 최종 출력 모두 일치) |
| 공개 장부 | RFC 9162(인증서 투명성 2.0) 2.1절 머클 트리, 포함 증명, 일관성 증명 | transparency-dev/merkle의 참조 시험 자료 | 루트 해시 9/9, 포함 증명 86건과 일관성 증명 98건 모두 참조 구현과 같은 판정(거부해야 할 172건 포함) |

| 글자 정규화 | 유니코드 NFKC (UAX #15) | Python 표준 라이브러리 | 기존과 같음 |

`check_standards.sh`는 세 공개 저장소를 고정된 커밋으로 받아 위의 확인을 다시 실행합니다(인터넷 연결 필요). 출력은 `results/STD-001_standards_check.txt`에 두었습니다.

장부를 머클 트리로 바꾸면서 달라진 점은 이렇습니다. 이전의 해시 연결 장부는 기록 하나를 확인하거나 장부가 고쳐지지 않았음을 확인하려면 장부 전체를 받아 다시 계산해야 했습니다. 이제 운영 기관은 기록 수와 머클 루트에 서명한 장부 머리를 공개하고, 기기 제조사는 시험마다 해시 5개 이하의 포함 증명으로 그 시험이 장부에 있는지 확인합니다. 누구나 해시 몇 개의 일관성 증명으로 오늘의 장부가 어제 공개된 장부를 고치지 않고 이어 쓴 것인지 확인할 수 있습니다. 운영 과정 시연(2.3)에 이 확인들과, 운영 기관이 지난 기록 하나를 고친 경우 일관성 증명이 성립하지 않아 변조가 드러나는 단계를 넣었습니다(57단계).

암호화 조회를 RFC 9497로 바꾼 뒤에도 E7의 600건, E9의 386건, E11의 2,100건에서 일반 대조와 같은 판정이 나왔습니다. 판정 규칙은 조각 값의 집합 연산이라 암호 방식과 무관하기 때문입니다.

### 3.15 조회 서버가 요청 크기에서 알아낼 수 있는 것 (E15)

암호화 조회는 질문의 조각을 조회 서버에 숨기지만, 서버는 질문마다 조각이 몇 개 왔는지, 언제 어느 서비스에서 왔는지는 봅니다. 서버가 모든 등록 문항과 바꿔 쓰기 방식을 알고 질문의 절반을 정답과 함께 이미 보았다고 가정하고, 조각 개수 하나만으로 무엇을 맞힐 수 있는지 쟀습니다(확인용 묶음, 문항 질문 2,040건, 일반 질문 4,559건).

| 방식 | 어느 문항인지 맞힘 (무작위 0.6%) | 문항 질문인지 구별 (0.5면 구별 못 함) | 서버 처리량 |
|---|---|---|---|
| 그대로 보냄 | 10.7% | 0.5396 | 1배 |

| 64개 단위로 채움 | 1.4% | 0.5367 | 1.468배 |
| 128개 단위로 채움 | 1.3% | 0.5225 | 2.031배 |
| 항상 512개 | 0.8% | 0.501 | 6.722배 |
| 질문 4건을 한 요청으로 | 0.7% | 0.5171 | 1배 |
| 질문 16건을 한 요청으로 | 0.5% | 0.5098 | 1배 |

그대로 보내면 서버는 문항 질문 10건 중 1건꼴로 어느 문항인지 맞힙니다. 여러 사용자의 질문 4건을 한 요청으로 묶으면 추가 처리량 없이 무작위 수준으로 내려갑니다. 대신 질문 4건이 모일 때까지 기다려야 합니다. 서비스별 요청 수와 시각은 어떤 방식으로도 가려지지 않습니다. 이를 가리려면 서비스가 일정한 속도로 빈 요청을 보내야 하고, 그 비용은 재지 않았습니다. 연습문제는 등록 문항과 같은 틀로 만들어 길이가 비슷하므로, 문항 질문인지 구별하는 값은 실제 대화에서는 달라질 수 있습니다.

### 3.16 조회 서버가 멈췄을 때 (E17)

```
python e17_outage.py
```

서비스는 문항의 조각 값을 미리 받아 두지만, 질문의 조각 값은 조회 서버만 계산할 수 있습니다. 그래서 서버가 멈추면 새 조각을 판정할 수 없습니다. 시험지에 인쇄한 표식은 조회를 쓰지 않으므로 영향이 없습니다. 질문의 30%가 문항 질문인 흐름에서, 서버가 멈춘 뒤 들어온 2,000건을 네 방식으로 판정했습니다(확인용 묶음, 규칙 R5).

| 멈추기 전 질문 수 | 보관된 조각 | 답을 계속함 | 모두 거절 | 보관한 조각 값으로 판정 | 조회 키 공개 | 정상 운영 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0% | 100% | 0% | 89.2% | 89.2% |
| 10 | 682 | 0% | 100% | 0% | 89.2% | 89.2% |
| 100 | 3,904 | 0% | 100% | 41.6% | 89% | 89% |
| 1,000 | 13,990 | 0% | 100% | 82.7% | 90.6% | 90.6% |
| 5,000 | 21,212 | 0% | 100% | 89.8% | 89.8% | 89.8% |

값은 문항 질문 가운데 거절된 비율입니다. "모두 거절"은 일반 질문도 전부 거절합니다. 보관한 조각 값으로 판정하면 모르는 조각을 일치하지 않는 것으로 치므로 일반 질문을 더 거절하지 않습니다(정상 운영에서 거절되지 않을 질문이 거절된 경우는 10,000건 중 1건). 시험이 시작되고 질문 1,000건이 지나면 정상 운영의 91.3% 수준이 유지됩니다. 같은 보관으로 평소 조회량도 줄어듭니다(5,000건 시점에 조각의 94.5%가 이미 보관된 값). 시작 직후에 멈추면 보관된 값이 없어 효과가 없습니다.

"조회 키 공개"는 시험 기관이 그 시험의 조회 키를 장부로 공개해 서비스가 직접 계산하게 하는 방식입니다. 판정은 정상 운영과 같아지지만, 그 시험이 끝날 때까지 내부자가 누구에게도 묻지 않고 추측을 대조할 수 있게 됩니다(E11의 보호를 포기). 시험마다 조회 키를 따로 써야 가능합니다. 어느 쪽을 기본값으로 할지는 운영 설계에서 정할 일입니다.

### 3.17 남의 질문을 거절되게 만들 수 있는가 (E18)


시험 시간에는 대화 전체를 판정하므로, 공유 문서나 앱의 지시문에 시험 문장이 들어 있으면 같은 대화의 일반 질문이 거절될 수 있습니다. 이렇게 할 수 있는 사람은 시험 중에 문항을 가진 사람뿐이고, 거절은 시험이 끝나면 풀립니다. 피해자의 대화(연습문제 4개와 후속 질문) 앞에 등록 문항의 일부를 심고 거절 여부를 쟀습니다(문항 180개). R5는 E19의 값입니다.

| 심은 분량 | R2 | R3 | R5 |
|---|---|---|---|
| 없음 | 0/180 | 0/180 | 0/180 |
| 20% | 0/180 | 0/180 | 0/180 |
| 40% | 0/180 | 0/180 | 0/180 |
| 60% | 0/180 | 0/180 | 3/180 |
| 80% | 0/180 | 0/180 | 22/180 |

문항 전문을 첫 메시지로 심고 일반 메시지를 이어 보내면, R3는 메시지 1개 뒤 5/180, 2개 뒤 0/180만 거절 상태로 남고, R5는 8개 뒤에도 180/180이 거절 상태입니다. 발문 10개만 심은 경우는 세 규칙 모두 0/60입니다.

두 결과는 같은 성질의 양면입니다. R3는 질문에서 일치하는 부분의 비율을 보므로 다른 글이 섞이면 거절하지 않습니다. 그래서 남용에는 강하지만 덧붙이기 회피(3.14)에 뚫립니다. R5는 문항이 얼마나 들어 있는지를 보므로 회피를 막는 대신, 문항의 대부분이 든 대화는 시험이 끝날 때까지 계속 거절합니다. 문항의 80%를 심으면 22/180, 전문을 심으면 모두 거절됩니다. 시험 문항을 가진 사람이 시험 중에 공유 문서나 앱 지시문에 문항을 넣으면 그 대화의 이용자는 시험이 끝날 때까지 답을 받지 못한다는 뜻입니다. 표의 R5는 E19에서 정한 값(90%)입니다.

### 3.18 규칙 R5의 채택과 값 (E19)

```
python e19_adopt_r5.py
```

E16에서 확인한 빈틈을 막기 위해 판정 규칙을 R5로 바꿨습니다. R5는 R3가 거절하는 질문을 모두 거절하고 세 가지를 더합니다.

- (가) 숫자가 있는 질문이라도 가장 비슷한 문항에 숫자가 없으면 글 경로로 판정합니다. 숫자가 있는 문항은 언제나 숫자 검사를 거칩니다.
- (나) 숫자 검사는 질문의 숫자가 모두 문항에 있거나, 문항의 숫자가 모두 질문에 있으면 통과합니다.
- (다) 문항과 닮지 않은 문장(자기 조각의 절반 미만이 그 문항에 있는 문장)을 버립니다. 남은 문장의 연속 구간이 문항 길이의 1.5배 이내이면서 문항 조각의 90% 이상을 담고 있으면 거절합니다. 숫자가 있는 문항은 그 구간에 문항의 숫자가 모두 있어야 합니다.

E16은 두 값을 연습문제 대화 300건으로 정했고(70%), 다른 묶음에서 16개 대화 100건 중 1~3건을 잘못 거절했습니다. 그 묶음들은 이미 본 것이라 값을 다시 고르는 데 쓸 수 없습니다. 그래서 선택용 묶음에 연습문제 16개 대화 600건과 32개 대화 300건을 더해 값을 다시 정하고, 어떤 실험에도 쓰지 않은 새 묶음(시드 20261130)에서 한 번 확인했습니다. 선택 규칙은 새 묶음을 보기 전에 정했습니다. 연습문제, 발문, 연습문제 대화를 하나도 거절하지 않는 값 가운데, 거절해야 할 질문을 가장 많이 거절한 값과 0.5%포인트 이내인 것 중에서 가장 짧은 구간과 가운데 비율을 고릅니다.

## 4. 결과를 읽을 때 유의할 점

- 모든 결과는 시뮬레이션입니다. 실제 카메라 촬영과 실제 인쇄물 측정은 시범 운영 단계에서 수행할 과제입니다.
- 최종 판독기(부분 판독과 확대·선명화)는 3.2 실험 결과를 확인한 뒤 개선한 것입니다. 개선 전 결과(33장)도 함께 공개합니다.
- 실험용 시험지에서는 낮은 인쇄 농도에서도 표식이 판독되었지만, 글자와 그림이 많은 실제 시험지에서는 현재 50%가 최저 농도입니다. 목표는 육안으로 거의 구분되지 않는 농도(`figures/sample_target_faint.png`)이며, 이를 위한 추가 연구를 진행할 예정입니다.
- 문항 내용 조회의 정확도는 실험용으로 만든 문항으로만 평가했습니다. 문항 조각 대조 실험(E3)과 3.5의 "바꿔 쓴 질문"은 띄어쓰기, 숫자 표기, 문장 순서, 일부 발췌, 단어 치환을 자동으로 적용한 것입니다. 문장을 완전히 바꿔 글로 입력한 질문은 탐지가 제한적입니다.
- E8의 문항은 영어 문장 유형 12개로 만든 실험용 문항입니다. 실제 시험 문항과 실제 학습 질문의 분포에서는 다시 확인해야 합니다. E8의 대조 시간(등록 6만 개에서 질문 1건당 약 40ms)은 단순 구현으로 잰 값이며 등록 문항 수에 비례해 늘어납니다.
- 숫자 없는 문항의 규칙은 실험 코드에서 검증했고, 시연에서는 `demo.py`의 [4]가 채택한 규칙 R5를 계산형 문항 하나로 보여 줍니다. `demo.py`의 [3]과 `operation_demo.py`는 숫자 있는 문항만 쓰는 처음 규칙 그대로입니다. 서술형 문항은 문장 틀로 만든 실험용 문항이고 실제 지문과 실제 학습 질문으로는 다시 확인해야 합니다. 일치율 기준 0.6은 이 실험용 문항에서 정한 값입니다. 최소 조각 수 20개는 E9의 질문에서는 결과에 영향을 주지 않았지만, 연습문제 일부만 입력한 질문에서는 영향이 컸습니다(3.12).
- E9에서 숫자가 빠진 채 20조각 이상이 등록 문항과 그대로 일치하는 인용은 거절됩니다. 문장 틀이 같은 연습문제에서 숫자 없는 부분만 입력한 경우가 이에 해당합니다. 뜻은 같고 표현을 전부 바꾼 질문은 조각 대조로 잡을 수 없습니다.
- E10의 글자 오류는 글자마다 독립으로 생기는 단순한 모형입니다. 실제 서비스가 사진을 읽을 때의 오류율과 오류의 모양은 재지 않았습니다.
- E11의 잠근 묶음은 시험 시작 전의 유출을 막을 뿐, 시험 중 내부자의 추측은 막지 못합니다. 열쇠를 시작 시각에 확실히 전달하는 방법(장부에 서명해 공개 등)은 운영 설계에서 정해야 합니다. 출제 틀을 모르는 현실적인 공격자의 추측 비용은 재지 않았습니다.
- E12의 값 되돌리기는 "A=168" 형식만 처리합니다. 숫자를 한글로 쓰거나 "첫째 값은 168"처럼 말로 풀어 보내는 경우는 유의어 치환과 같은 한계로 남습니다. 대화 전체 판정은 시험 시간 동안 대화 내용을 서비스 안에서 잠시 모아 두어야 합니다.
- E14의 연습문제 지문은 등록 문항과 같은 문장 틀로 만들었으므로, 연습문제 일부 오인율은 실제보다 높게 나왔을 수 있습니다. 실제 교재와 실제 시험 지문으로 다시 재야 합니다. R3는 E9, E10, E12의 결과 파일에 반영했습니다.
- E13의 처리량은 이 저장소의 Python 구현과, 그 안의 타원곡선 곱셈(OpenSSL)만 잰 값입니다. 최적화된 RFC 9497 라이브러리의 실제 처리량은 재지 않았습니다. 시험 시간에는 협조하는 서비스에 들어오는 모든 글 질문이 조회 대상이 되므로, 학교 시험이 몰리는 기간의 실제 질문량은 서비스와 함께 확인해야 합니다. 시험 기관 서버가 멈췄을 때 답할지 막을지의 기본값도 운영 설계에서 정해야 합니다.
- E16에서 그때까지의 규칙 R3의 빈틈이 확인되어 규칙을 R5로 바꿨습니다(3.14, 3.18). 명세, 연동 확인용 시험 값, `demo.py`의 [4]는 R5이고, `demo.py`의 [3]과 `operation_demo.py`는 숫자 문항만 쓰는 E7 규칙 그대로입니다. R5는 연습문제 32개를 이어 붙인 대화를 100건 중 1건 잘못 거절했고, 문항 대부분이 든 대화를 시험이 끝날 때까지 계속 거절합니다(3.17). 두 낱말마다 군말을 끼운 질문, 문장을 전부 바꾼 질문, 번역한 질문은 R5로도 막지 못합니다. 숫자 하나를 빼고 다른 숫자를 더하는 식으로 숫자 검사의 양쪽 조건을 모두 깨는 경우도 재지 않았습니다.
- E16의 "문장을 전부 바꾼 질문"은 손으로 쓴 바꿔 쓰기 틀로 만든 것이고, AI가 바꿔 쓴 문장으로는 재지 않았습니다. 축소 벡터는 신경망 문장 임베딩이 아닙니다. 신경망 임베딩이 바꿔 쓴 질문을 얼마나 잡고 연습문제를 얼마나 오인하는지는 재지 못했습니다.
- E15는 조각 개수 하나만 보는 관찰자를 가정했습니다. 요청 시각의 간격이나 같은 사용자의 연속 요청을 함께 보는 관찰자는 재지 않았습니다. E17의 질문 흐름(문항 질문 30%, 문항마다 같은 빈도)은 가정입니다.
- 암호화 조회의 처리 시간은 이 저장소의 구현을 CPU 1개로 측정한 값입니다. 실제 운영 규모의 처리량은 공용 조회 서버를 구현한 뒤 측정해야 합니다. 표준 적합성(3.13)은 공식 시험 값과 참조 구현의 시험 자료로 확인한 것이며, 제3자의 구현 감사나 상호 운용 시험을 거친 것은 아닙니다.
- 상용 AI 판독 시험은 한 모델(GPT-Astra), 사진 36장의 결과입니다. 1차 질문의 원문은 보관하지 못했습니다(`results/E5-003_prompts.md`). 모델이 바뀌면 다시 확인해야 합니다.
- 라이브러리 버전이 크게 다르면 영상 처리 결과가 소수의 시행에서 달라질 수 있습니다. 시험한 버전은 `requirements.txt`에 적었습니다.
- 사용자가 직접 구성한 로컬 AI, 협조하지 않는 서비스, 사람에 의한 대리 풀이는 본 제안으로 막을 수 없으며 기존 단속과 감독이 담당합니다.
